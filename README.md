# GitHub-Trending-Analysis

A small Exploratory Data Analysis (EDA) project that collects and analyzes high-star GitHub repositories across curated topics and categories to identify trends (languages, stars, forks, activity, etc.).

## Repository structure
- `EDA GITHUB (1).ipynb` — Jupyter notebook that queries the GitHub Search API, performs EDA, and saves results.
- `github_repository_analysis.csv`, `github_repositories.csv` — CSV outputs generated by the notebook.
- `GitHub_Repository_EDA.pptx` — Presentation summarizing findings.
- `GitHub Report.pdf` — PDF report export.

## Summary
The notebook groups topic keywords into categories (Data Science, Web Development, Cybersecurity, Full Stack, Database, JavaScript Frameworks, UI/UX, API). For each topic it collects the most-starred repositories and compiles a dataset with fields:
- Category, Topic, Repository, Owner, Repository URL
- Language, Stars, Forks, Watchers, Open Issues
- Created At, Updated At

The final dataset is saved as `github_repository_analysis.csv`.

## Usage
1. Open the notebook `EDA GITHUB (1).ipynb` with Jupyter Notebook / JupyterLab.
2. (Recommended) Use a GitHub personal access token to reduce API rate-limit and 403 errors:
   - Create a token on GitHub (no special scopes needed for public repo search).
   - Store it as an environment variable, for example:
     - macOS / Linux:
       ```bash
       export GITHUB_TOKEN="ghp_xxx..."
       ```
     - Windows (PowerShell):
       ```powershell
       $env:GITHUB_TOKEN="ghp_xxx..."
       ```
   - In the notebook, add the token to request headers:
     ```python
     import os, requests
     headers = {"Authorization": f"token {os.environ.get('GITHUB_TOKEN')]}"
     response = requests.get(url, headers=headers)
     ```
3. Run the notebook cells to collect data and perform EDA. The notebook includes a polite `time.sleep()` between requests.

## Notes & troubleshooting
- The GitHub Search API is rate-limited; unauthenticated requests are especially constrained and may return HTTP 403. Use an access token.
- Search results are paginated. The notebook currently requests `per_page=100`. If you need more results per topic, add pagination handling (iterate `page=1..n`).
- Some repositories may have null `language`; consider normalizing or imputing language where needed.
- If you get frequent 403 responses even with a token, verify token validity and that you're not hitting secondary rate limits.

## Suggestions for improvement
- Add pagination to collect more than 100 results per topic.
- Cache results or save intermediate snapshots to avoid repeated API calls.
- Enrich each repo with additional metadata (topics, license, README length, recent commit activity).
- Store results in a small DB (SQLite) for queries and reproducibility.
- Add automated scheduled snapshots (e.g., GitHub Actions) to monitor trends over time.

## Example: collecting repos (snippet)
```python
import os, requests, time
headers = {"Authorization": f"token {os.environ.get('GITHUB_TOKEN')}"}
url = "https://api.github.com/search/repositories?q=data-science&sort=stars&order=desc&per_page=100"
resp = requests.get(url, headers=headers)
if resp.status_code == 200:
    items = resp.json().get("items", [])
else:
    print("HTTP", resp.status_code, resp.text)
time.sleep(2)
```
